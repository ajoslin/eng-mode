# Model tier handoff and escalation

## Sub-features

An `/eng-mode` prompt starts the session on the `@panel_fable` model role at low thinking. The `handoff` tool ends the turn, switches the session to `@eng_mode_easy` at medium thinking, and starts a fresh turn on the cheap model; below 80k context tokens the conversation is kept intact, above it the conversation is compacted into the brief first. The `escalate` tool compacts the conversation on the cheap model, switches back to `@panel_fable`, and is terminal: a later `handoff` returns `refused: the execution tier already escalated this task; finish it on the expert tier`. Calling a tool on its own tier has no side effects: `escalate` on the expert tier returns `already on the expert tier`, `handoff` on the cheap tier returns `already on the execution tier`. Thirty tool results on the expert tier without a `handoff` render an `Exploration check` steer once; an `edit` or `write` to a real file path (not an `xd://` device) before that point cancels the steer for the session. Two consecutive failing gate commands in `bash` on the cheap tier render an `Escalation check` steer. A gate command is one whose text contains `bun test`, `bun run check`, `tsgo`, `pytest`, `cargo test`, `go test`, `npm test`, `vitest`, or `jest`; a passing gate resets the streak and a non-gate command leaves it alone. Escalation remains refused (`refused: not stuck yet (…)`) until that two-failure streak or forty cheap-tier tool calls, and then succeeds only when `evidence` contains, as its own verbatim lines, the most recent failed `bash` command and one non-empty rendered output line from that failure. A prefix such as `Failed command:` on either line makes the match fail.

## How to get to it (user POV)

Launch OMP with the local Eng Mode extension. The disposable profile must resolve `eng_mode_easy` and `panel_fable`. Copy the workstation `config.yml` and `models.yml` into the profile's `agent/` directory before launch.

## Driving it with OMP TUI

1. Send `/eng-mode Reply exactly EXPERT_OK and stop.` Confirm the status bar model stays on the `panel_fable` model and the agent replies `EXPERT_OK`.
   Then send `Read package.json thirty-two times, one read call each, then reply DONE.` Confirm `◆ Exploration check` renders exactly once and the model answers it in its reply. The model usually issues the reads as one parallel batch, so the steer appears after the batch that contains the thirtieth result, not between individual reads.
2. Send `Call the handoff tool with brief "run bun test ./nonexistent.test.ts twice, one call each, then report" and do nothing else.` Confirm the `Handoff` tool invocation renders, the status bar model changes to the `eng_mode_easy` model, and a new user turn beginning `You are the execution tier.` starts. Confirm its brief says to execute and fix failures, not to escalate for topic, scope, or expert review. The cheap model runs both commands (exit 1 each), then `◆ Escalation check` renders.
3. Ask the cheap model to call `escalate` first with evidence `needs expert review to ship`. Confirm the result is exactly `refused: evidence must quote the most recent failed command and one rendered failure line`. Then ask it to call `escalate` with evidence set to exactly two lines and nothing else: `bun test ./nonexistent.test.ts` and `Test filter "./nonexistent.test.ts" had no matches in --cwd="<checkout>"` (copy the rendered line verbatim). Confirm the result `Escalating to the expert model. This turn ends; a fresh turn continues on the new model.`, the status bar returns to the `panel_fable` model, and a user turn beginning `You are the expert tier.` is answered. Send `Call the escalate tool with reason "x" and evidence "y", then call the handoff tool with brief "again", and report both exact results.` Confirm `already on the expert tier` and `refused: the execution tier already escalated this task; finish it on the expert tier`.

## Gotchas

When the session holds fewer than 20k context tokens, escalation skips compaction (OMP's `prepareCompaction` has nothing to summarize below `keepRecentTokens` and the TUI would render `Compaction failed`), so early escalations show no compaction entry; above it the session JSONL shows a `compaction` row before the `model_change`. A handoff shows one only above 80k context tokens. Model switches persist for the rest of the session. Relaunch before other recipes that expect the launch model. The expert model may call `handoff` unprompted during any long multi-tool drive; when it does, the rest of that drive runs on the cheap tier and the steps above that need the expert tier require a relaunch.
