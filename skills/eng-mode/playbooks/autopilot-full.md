### Autopilot-full

**Drive a queue of independent PRs through verified landing when the operator grants merge authority. The root owns verdicts and coordination, never a PR.**

1. Mark operator-owned items. They stop at merge-ready. State the protocol and wait when asked for a plan. Begin writes only after an explicit go, then keep the falsifiable program objective in `goal` and the finite queue in `todo`.
2. Assign every PR one persistent accountable owner on an exclusive branch. That owner, or a named successor on the same branch, owns build and PR creation through **Opening a PR**, proof on the real surface through `verify-project`, triage, cleanup, the decision trail, and Babysit to merge-ready. It also owns any fix-forward and repeats those stages for the new head. After its first push, the owner pushes its branch again after every verifiable unit (hooks on, a WIP commit is fine). As soon as a subagent starts, the owner adds its id, expected runtime (at least the longest past run of that kind), and state to an uncommitted `children.tsv` next to its decision trail. The owner does the first rebase onto trunk before its code-ready report and Babysit, whether or not trunk has drifted. In fix rounds it keeps that merge base. It rebases again only at merge prep (step 5), on a `git merge-tree` conflict with trunk, or on a CI failure that comes from a change on trunk. It publishes each rebase of its own branch with `git push --force-with-lease` after an `ls-remote` check, and never force-pushes a shared branch. When the shipped code is final, after cleanup and `no-comments`, it reports the code-ready head SHA, and the SHA of each later push that changes the patch. Proof, CI, and Babysit then run in parallel with the root's lanes. Before a push that starts a round, it runs the pre-review checks `project-standards` names for the touched paths on the committed head. A hook pass is not proof. The root never implements or babysits a PR.
3. Run self-contained owners in parallel from the correct base. Serialize only genuinely overlapping writes. Route dependent work to **Autopilot-stack**. Do not manufacture a stack for independent work.
4. A round starts at the owner's code-ready head SHA and at each later push that changes the patch. At each round's SHA, the root commissions three independent lanes and aggregates `VERIFIED(<sha>)`: repository gates, live real-surface proof, and receipts-plus-diff audit that distrusts the PR body. Run the audit as two or more review agents with the full brief, each with one main focus, such as consumer parity with trunk, lifetimes and races, or data and config safety. The merge needs a clean verdict from the round whose patch matches the merge-ready head. The root audits the receipts in the merge-ready report before the verdict. Each lane returns `PASS`, `PASS+NOTES`, or `FAIL`, pinned to that exact SHA. Any `FAIL` blocks. Retain notes in the aggregate verdict. The root never serves as a lane. Post the verdict on the PR. Send every proven finding to the owner in one fix-forward. A defect that a lane filed as a note is a finding. For each behavior finding, ask for a red test that covers every site with the same defect, or a repro receipt where no test can show it, and add that defect to the next round's review brief. A new SHA voids the verdict unless the patch-id rule in `shipping.md` keeps a lane's result valid. Otherwise run the lanes again.
5. The root countersigns the current `VERIFIED(<sha>)` and keeps the queue, ownership, liveness, replacements, and any new pinned gate or budget raise. The PR owner may land only by running **Shipping** with explicit merge authority, that countersign, and Babysit merge-ready at the same SHA. Merge prep never comes before a round's lanes start. It ends with a rebase onto current trunk, a new head SHA report, and CI passing on that head. Right before landing, fetch trunk and check that `git merge-tree` of the head against trunk is clean and that no path in `git diff --name-only $(git merge-base HEAD origin/main) origin/main` is a path the PR changes or a path that decides which CI runs for it. If either check fails, rebase again and repeat. After the merge, a fresh owner takes the next self-contained item, per Eng Mode's fresh-agents rule. Babysit never merges. The root never merges. Operator-owned items remain waiting for the operator.
6. Use only `eng-github` for PR state and watching. Freeze ordered PR references and head SHAs, then follow `babysit.md` watcher steps. Start one managed `eg watch` under `hub start` and run one `hub wait` per event. Classify each wake as `WAITING`, `READY`, `ADVANCE`, or `COMPLETE`. If an `eg` command exits 75, record the printed reset time and wait until it passes. Never retry the failed command before then or poll. Never fall back to raw `gh`, `curl`, or another tool. Use `eg api` or `eg graphql` for undocumented operations. If an operation is missing, stop. Prefer the blocking wait. For repeated audit turns, use `loop` against the active goal with an event-driven wake or an hourly audit tick.
7. On every wake, probe each owner, reconcile `eg watch` events, verdict SHA, Babysit state, and decision trail. Re-read this playbook from trunk and audit the operation against it. Count only side effects, commits, pushes, PR, check, or thread changes, proof receipts, or trail records as progress. A lane that errors, or passes its expected runtime without a side effect, is stuck. Replace a stuck owner immediately with a named successor on the same exclusive branch. Do not leave the PR ownerless. Run the same stuck test over every owner's `children.tsv`. Have the owner record each stuck subagent as stuck and replace it if its work is still needed, or do both yourself when the owner cannot. A stall never proves or drops the work. End the tick only when no delegated work is left, even after the last merge. After batched merges, run a retrospective and post-merge review-comment sweep.
8. On an operator hold or stop, immediately send every owner a zero-write instruction, stop the loop, and preserve branches, briefs, trails, watcher state, and queue placement for resumption.

**Reply:** for each item, report owner or successor, PR, current head SHA, `READY` / `WAITING` / `ADVANCE` / `COMPLETE`, Babysit gate, `VERIFIED` verdict and lane receipts, countersign, merge or next action, operator gates, and decision-trail location.
