### Autopilot-stack

**Build and verify one dependent, review-first PR chain. The root owns topology and the operator owns landing. Ordinary coherent work stays one PR.** **Autopilot-full** holds except for how verified work leaves. Each wake re-reads both playbooks from trunk, and this one wins where they differ.

1. **Run Autopilot-full's owners, minus the landing.** Owners report `STACK-READY` in place of merge-ready. They never rebase onto another branch, trunk included, and never force-push onto another base, retarget, merge, close a PR, arm auto-merge, or run `eng-github stack` commands, because the root owns the chain's topology and the operator owns the landing. When an item depends on another, its owner branches from that item's branch, not from trunk. Run independent owners in parallel. Do not serialize implementation just because append order is linear.
2. **Verify per Autopilot-full step 4.** `STACK-READY(<sha>)` means that exact SHA is `VERIFIED`, Babysit reports it merge-ready at the same SHA, the verdict is posted, and the root has countersigned it and appended it with `eng-github stack add`. A new SHA voids both states unless the single verifier or the patch-id rule in `shipping.md` carries them.
3. **Give the topology one writer.** Owners push only their own branches and report each tip and its intended parent. Only the root runs `eng-github stack submit`, `add`, or `rebase`, because two writers on one chain undo each other. Append each `STACK-READY` candidate in dependency order. An owner takes the root's push as its new base and lease, and on a conflict resolves its own slice for the root to push.
4. **Absorb drift at the root.** Until landing starts, apply Autopilot-full step 5's risk test to each layer and run `eng-github stack rebase` where it calls for one. Then apply the patch-id rule layer by layer, since a layer's base is its parent.
5. Use only `eng-github` for PR state, topology, and watching, with the watcher, exit-75, and `loop` rules of Autopilot-full step 7. Count topology changes as progress in Autopilot-full step 8's stuck test.
6. **Deliver the chain, then keep your hands off it.** Each layer carries its verdict in its PR. Nothing in this playbook merges, closes, or arms auto-merge. The operator lands through **Shipping**. There `eng-github stack merge` lands every layer below the target, so nothing needs retargeting after a merge. Once landing starts, nobody writes to the stack, because a second writer breaks a landing in flight. A mid-landing problem goes through the root to the operator, and any fix waits for the operator's go.

**Choosing between the autopilots.** Autopilot-full when the PRs are independent and landing authority is granted. Autopilot-stack when the operator wants review before landing, the work is sequenced or coupled, or merge authority is withheld.

**Reply:** catch the operator up per the **ketchup** skill. Report stack root and tip. For every PR, cover owner or successor, current head SHA, intended and actual base, `READY` / `WAITING` / `ADVANCE` / `COMPLETE`, Babysit gate, posted `VERIFIED` verdict and lane receipts, `STACK-READY` state, countersign, decision-trail location, and any parked or excluded item with its reason.
