### Autopilot-stack

**Build and verify one dependent, review-first PR chain. The root owns topology and the operator owns landing. Ordinary coherent work stays one PR.**

1. State the protocol and wait when asked for a plan. Begin writes only after an explicit go. On a hold or stop, send every owner a zero-write instruction, stop the loop, and preserve branches, briefs, trails, watcher state, and stack placement for resumption.
2. Assign each PR one persistent accountable owner on an exclusive branch. That owner or a named successor on the same branch owns build and PR creation through **Opening a PR**, proof on the real surface through `verify-project`, triage, cleanup, the decision trail, and Babysit to merge-ready. Owners push after each verifiable unit, keep `children.tsv`, and report a code-ready head SHA per `autopilot-full.md` step 2. Owners never rebase, force-push, mutate stack topology, or land. Run independent owners in parallel. Serialize overlapping writes.
3. The root verifies each round per `autopilot-full.md` step 4. Each round starts at the code-ready head SHA and every later push that changes the patch. The root aggregates `VERIFIED(<sha>)` from repository gates, live real-surface proof, and two or more focused receipts-plus-diff audit lanes. Each lane returns `PASS`, `PASS+NOTES`, or `FAIL` for that SHA. Any `FAIL` blocks. The root never serves as a lane. Post the verdict on the PR and send every proven finding to its owner in one fix-forward.
4. `STACK-READY(<sha>)` means that exact SHA is verified, Babysit reports it merge-ready at the same SHA, the verdict is posted, and the root has countersigned and safely appended it with `eg stack add`. A new SHA voids both states unless the patch-id rule in `shipping.md` keeps them valid. Otherwise, the owner fixes forward, all three lanes verify again, and the root countersigns the replacement verdict.
5. The root alone owns stack topology. Compare current head and base, absorb trunk or parent drift with documented `eg stack` commands, and use patch identity to decide whether verification must run again. Append only a candidate whose exact SHA is verified, Babysit merge-ready, posted, and countersigned. Owners report branch tip and intended parent but never run topology commands. Keep one topology owner per stack. Do not serialize independent implementation just because append order is linear.
6. Use only `eng-github` for PR state, topology, and watching. Freeze the ordered PR references and head SHAs, then follow `babysit.md` watcher steps. Start one managed `eg watch` under `hub start` and run one `hub wait` for each event. Classify wakes as `WAITING`, `READY`, `ADVANCE`, or `COMPLETE`. For exit 75, record the printed reset time and wait until it passes. Never retry the failed command before then or poll. Never fall back to raw `gh`, `curl`, or another tool. Use `eg api` or `eg graphql` for undocumented operations. If an operation is missing, stop. Neither the root nor owners arm merge-when-ready. The operator lands through **Shipping**.
7. Prefer the blocking `eg watch`. For repeated audit turns, keep the objective in `goal` and use `loop` with an event-driven wake or an hourly audit tick. On each wake, re-read this playbook from trunk, run the stuck test from `autopilot-full.md` step 7 for every owner and `children.tsv`, then probe each owner. Count only side effects, commits, pushes, PR, check, or thread changes, proof receipts, topology changes, or trail records as progress. Replace a stuck owner with a named successor on the same exclusive branch.
8. Deliver one linear chain for bottom-to-top review. Nothing in this playbook merges, closes, or arms auto-merge.

**Reply:** report stack root and tip. For every PR, owner or successor, current head SHA, intended and actual base, `READY` / `WAITING` / `ADVANCE` / `COMPLETE`, Babysit gate, posted `VERIFIED` verdict and lane receipts, `STACK-READY` state, countersign, decision-trail location, and any parked or excluded item with its reason.
